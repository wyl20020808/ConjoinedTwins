# 通用游戏计算优化

历史基线说明：本文数据来自未承接后续追击、动态战斗和机关增密的副本。当前已整合这些功能，来源及当前验证见 [最新玩法整合](LATEST_GAMEPLAY_INTEGRATION.md)；不得将本文的减耗比例或旧版本通过项直接当作整合版验收。

2026-10-18，继续当前任务分支 `fix/dense-scene-performance`。本轮目标是降低游戏自身的计算量，不再把本机核心亲和性、Windows 能效配置或更换渲染后端作为通用优化成果。

## 源码改动

1. 每个运动子步只构造一次角色与新旧绳段的保守包围盒。远处工业机关不再各自复制、遍历完整绳索，近处机关继续执行原时间分片、相对运动与绳段连续碰撞。
2. 固定位置陷阱、柱体和完整飞行包络先做保守范围排除。动态前向威胁有额外的阻绳状态更新，因此保留原循环；未知机关类型也保留完整检测。候选列表维持源列表次序，不改变首次命中及伤害处理顺序。
3. 扫杆身体检测先排除整个旋转盘都无法触及的路径。范围包含角色半径和圆弧误差余量，盘内仍使用原旋转分片算法，不把旋转盘永久当作实际碰撞体。
4. 地形沿道路分桶，每个固定步内只查询相关地形。桶只覆盖父模拟的一次固定步，返回后立即释放；外部直接修改布局的查询仍读取实时几何。渡船沿横向移动，升降和开桥只改变高度，现有地形的纵向包络在固定步内不变。
5. 地面缺口先使用原有类型索引，仅采样缺口和塌陷机关，避免为每个采样时间重新遍历整章其他机关。

没有减少动物、机关和场景密度，没有改变 120 Hz 内部固定模拟、三个运动子步、绳索粒子数、十二轮约束、伤害数值或碰撞精度。本轮只改动 `road_run.gd`、`journey_run.gd` 两个生产脚本，使用所有目标平台共用的 GDScript；未修改渲染后端、项目画质、CPU 核心设置或系统配置。

## 同条件测量

基线是本轮修改前、已包含上一轮 UI / 伤害及密集场景优化的源码快照，不是最初未优化版本。固定种子 8123，约 480 米安全观察点，三章各推进 360 个固定步，即三秒模拟时间，保持 running。每章保留 205–264 个机关、65–87 个事件。

Godot 4.7.1 headless 原启动参数；不设置亲和性、进程能效或渲染后端。修改前后新进程串行交错运行各三次，表内为三次中位数的中位数。数据表示本机 CPU 固定步耗时，包含探针开销，不是整机 FPS 或其他设备实测。

| 章节 | 本轮前固定步 | 本轮后固定步 | 降低 | p95 前 / 后 |
| --- | ---: | ---: | ---: | ---: |
| 穿林入村 | 4.453 毫秒 | 3.615 毫秒 | 18.8% | 4.826 / 3.991 毫秒 |
| 水车河道 | 4.046 毫秒 | 3.311 毫秒 | 18.2% | 4.451 / 3.629 毫秒 |
| 矿道归航 | 4.134 毫秒 | 3.345 毫秒 | 19.1% | 4.508 / 3.698 毫秒 |

同一段三秒模拟的工作量变化：

| 章节 | 工业机关精确检测次数前 / 后 | 普通机关身体检测次数前 / 后 |
| --- | ---: | ---: |
| 穿林入村 | 20,520 / 1,080 | 86,400 / 6,480 |
| 水车河道 | 22,680 / 1,080 | 69,120 / 6,480 |
| 矿道归航 | 20,520 / 1,080 | 73,440 / 6,480 |

这些调用次数由算法决定，不依赖某款 CPU。三轮前后每章最终同步指纹均一致。耗时收益不能与上一份不同夹具的 21%–23% 直接相加，也不能保证每个平台都获得相同比例的提升。
