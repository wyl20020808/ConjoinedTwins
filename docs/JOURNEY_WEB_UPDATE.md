# 连续旅程网页版与单人人机（2026-10-15）

默认生产场景仍为 `scenes/journey.tscn`。同一章节中连续经过林外陆地、森林、村庄与出口，场景切换不重开关卡。松开前进停步，不能后退。

## 三种游玩模式

- 单人＋人机：网页版默认。玩家使用 W/A/D 和空格；人机控制 02。
- 本地双人：01 使用 W/A/D 和空格；02 使用方向上/左/右和回车。
- 远程双人：两人打开同一版本网页，选择远程双人并连接队友，任一方点击开始。每人控制自己的角色；W/A/D 或方向键均可用，空格或回车跳跃。手机使用触控。

网页默认连接同域名的 `/ws`，仍可通过 `?server=`指定服务器。远程输入通过中继按 60Hz 广播，各客户端执行相同固定步模拟；暂停、继续、重试通过同一帧序列生效。

## 人机同步优化

`journey_buddy.gd` 为新连续旅程提供独立控制器，旧自动推进场景的 AI 保留供历史恢复。新控制器只输出普通方向和跳跃键，与真人共用速度、碰撞、跳跃、地面支持与绳长规则，不修改角色位置。

控制器预测前方地面、塌陷、动态事件和绳索危险；玩家松开前进时等待，前进时跟随。供能门与双踏板按真人所在侧选择另一侧，支持交换左右角色。救援时通过普通跳跃脉冲参与拉起，结算时仅确认人机自己的角色。

人机使用短期局部预测，并非任意输入都能保证通关。玩家仍需选择路线、跳跃并配合救援。

## 协议与发布

协议升为 2，避免旧自动道路客户端与新连续旅程客户端混局。双方都应关闭旧标签页后重新打开网页；旧原生包需要重新导出才能连接新版中继。

复用 `build-tools/prepare_web.py` 和项目本地 Web 模板缓存导出。生产部署使用 `build-tools/journey/publish_web.py`，显式传入网页目录、服务目录和 relay LaunchAgent 路径。脚本备份旧网页及 plist，以独立最小工程发布中继；服务重载后核对本地 `version.json`，失败时恢复。Caddy 与其他开发服务保持运行。

`version.json` 包含源码提交、协议、发布时间和每个导出文件的 SHA-256。首次下载的游戏 PCK 约 84MiB，后续由浏览器缓存。

## 验证证据

- `tests/journey_solo.gd`：372 项检查，覆盖停止/前进/不后退、绳长、暂停、双侧机关站位、真实救援输入、低栏跳跃与结算确认。
- `tests/journey_solo_campaign.gd`：只驱动真人输入，人机自主操作，三个章节均到达结算，6 个区域全访问、两道出口机关均开启。没有瞬移或放宽碰撞。
- `tests/journey_online.gd`：真实中继与两个生产场景；WebSocket 以及 ENet/WebSocket 混合连接；至少 420 个共同帧连续且哈希一致；共享开始、暂停/继续、重试，人机在远程模式停用；事件阶段参与哈希。
- `tests/journey_touch.gd`：5 项检查，短触跳跃只发送一次、不能触控后退、正常方向输入与暂停禁用。
- `build-tools/journey/web_smoke.cjs` 与 `web_online_smoke.cjs`：隔离的 headless Chromium 实际加载最终 WebAssembly，核对 UI、单人移动与人机跟随、暂停、双网页连接、不同角色和同步状态。通过 `PLAYWRIGHT_MODULE`、`CHROMIUM_EXECUTABLE` 指定本地运行环境；`JOURNEY_URL`、`JOURNEY_SERVER` 可指定部署入口。

浏览器测试仅在 `?verify=1` 时读取 `window.__ctJourney` 状态，接口不写入游戏状态。证据保留在被忽略的 `build-tools/journey/evidence/web-update/`，构建产物不提交。

场景测试退出时，Godot 对刚播放的 WAV 留有 2 个音频对象警告（两个客户端为 4 个）；未出现脚本错误。该退出清理警告仍保留记录，不能宣称零警告。

以上为执行者自测；Controller 独立测试未运行（`tests=[]`）。桌面可见 GUI 和手机真机的触屏、音频、帧率与公网完整对局仍待用户试玩，记为 `deferred_by_work_mode`；headless 成功不等同于这些项目验收通过。
