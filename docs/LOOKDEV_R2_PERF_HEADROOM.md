# 第二轮画面 · 第一刀：性能余量

日期：2026-10-20。分支：`art/perf-headroom`（从 `test@d6f4c87` 新建）。

## 问题

第一轮的帧时间都是在 1280×720 下测的。实际窗口放大或全屏后（开发机外接 4K 屏），3D 按窗口像素渲染，森林段帧时间远超 60 帧预算。后续几刀（光源、能量绳、夜景、水面）都要占用 GPU，必须先腾出余量。

固定种子、M4 / Metal 下的定位结果（`builds/round2/tools/bench.gd`，每项 240 帧，关闭垂直同步）：

| 1920×1080 森林段 | 帧时间 |
| --- | ---: |
| 改动前（原生 + MSAA 2×、远景景深、SSAO 中档） | 22.8–27.9 ms |
| 关闭阴影 | 基本不变（阴影不是瓶颈） |
| 渲染分辨率降到 0.5 | 约 16 ms（像素填充受限） |
| 关闭远景景深 | 约 −3 ms |
| SSAO 改为低档半分辨率 | 约 −2–3 ms |

逐网格统计显示，镜头可见范围内蕨类每株约 1,000 面、共约 80 万面，灌木约 50 万面，绘制距离都是 170 米；70 米以外被树干与林雾遮住，几乎看不到。

## 改动

- **自适应时间性超分**（`journey_view.gd: apply_desktop_quality`）：窗口高度不超过 800 像素时保持原生分辨率 + MSAA 2×，即原有 720p 观感不变；更高时改为时间性超分，内部渲染高度约 800 像素，最低 0.34 倍。macOS 用 MetalFX Temporal，其他桌面平台用 FSR2，同时得到时间性抗锯齿。窗口尺寸变化时重新计算。`canvas_items` 拉伸模式下可见矩形固定为 1280×720，所以按窗口像素判断。
- **SSAO 低档半分辨率**；近景接触暗部基本保留。
- **去掉远景景深**：0.05 强度在截图中看不出来，纵深由距离雾与大气透视表现。
- **林下层绘制距离**：蕨类、灌木、草和蕨床在桌面端 75 米（网页 / 移动端 60 米）外不再绘制；树木及其 LOD 不变。
- 网页与移动端路径不变。

## 结果

| M4 / 固定种子 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 1080p 森林 | 22.8–23.9 ms | 15.3 ms |
| 1080p 村庄 | 14.3–15.7 ms | 9.9–10.1 ms |
| 1080p 矿道 / 设施 | 10.8–12.6 ms | 7.7–8.2 ms |
| 720p 森林 | 14.6 ms | 13.1–13.3 ms |
| 720p 村庄 | 8.3 ms | 7.5–7.7 ms |

机器连续跑基准会热降频，同一配置在不同轮次可能相差 1–3 ms；上表取同一轮相邻测量。1080p 截图见 `builds/round2/p1/`（本地，不入库）：远处树林、地平线与改动前一致，近景没有可见的超分重影。

## 未验收

- 4K 全屏、Windows FSR2 实机均未测；MetalFX 在快速移动的细绳与粒子上是否有拖影，需要真人跑图确认。
- 森林段在 1080p 下只剩约 1.3 ms 余量；后续几刀若在森林加入光源，需要同步再测。
