# 玩法扩展路线图

记录日期：2026-10-14。本文是后续扩展方向的讨论记录与待办，不代表已实现或已验收。实现后在对应条目注明分支、提交和报告。

## 当前状况判断

- 危险种类已有约二十种，但多数解法相同：两人共同换到同一侧。继续增加同类障碍，收益递减。
- 绳索目前主要是"限制"：拉住、挂柱、把队友拖下悬崖。真正"用绳子做事"的只有充能闸门。这是本作区别于普通跑酷的核心，尚未充分利用。
- 新段落的成本高：每加一种段落，都要写对应的路线控制器，经生产固定步验证才能进入随机池。这保证了随机地图不出现死局，但拖慢内容扩展。
- 2026-10-14 的路面加宽（±16 米）、独木窄桥、镂空断崖和失败演出尚未经过真人试玩。

## 方向一：绳子从限制变成工具（优先）

| 想法 | 说明 | 代价 |
| --- | --- | --- |
| 坠落救援 | 一人踩空后挂在绳上，队友疯狂按键把人拉上来，频率不够则共同坠落。失败瞬间变成合作时刻。 | 中：推翻"绳索不承重"设定，新增救援状态与演出。**已选为下一项，设计见下文。** |
| 荡绳过崖 | 一人站稳当支点，另一人借绳摆荡越过缺口，然后交换。 | 大：需要摆荡物理与新的路线验证。 |
| 绳子绊敌 | 两人分侧把绳拉紧，横在路上绊倒迎面冲来的低矮敌人。奖励分侧站位，与现有"必须同侧"形成对比。 | 中：复用绳段碰撞检测，新增敌人类型。 |
| 绕柱开关 | 用绳子绕住机关柱，再共同拉紧来开门。 | 中：复用绕柱求解与闸门框架。 |

## 方向二：关卡结构与节奏

- 分岔路：前方分成两条路，两人需协商走哪条；分开走时，绳长限制两条路的间距。
- 追逐段：后方有巨石或塌方追来，压缩后撤空间，制造神庙逃亡式压力。
- 每关的特色：三关目前共用随机池，可给每关一个专属机制和结尾高潮段。
- 节奏编排：随机抽签改为"紧张—喘息—紧张"的节奏模板，再在模板内随机。

## 方向三：打磨现有内容（穿插进行）

- 中途存档点：一关约 100 秒，失败从头来挫败感重。可在关卡中段（例如 50%）设检查点，失败后从检查点重试，检查点之前的收益保留。
- 失败原因可视化：场景文字标签目前全部隐藏，可在失败演出时高亮导致失败的危险或绳段。
- 降低新段落的制作成本：用"路线关键点"声明式描述段落，替代逐段手写路线控制器，作为后续扩展的基础工作。

## 推荐顺序

1. 试玩当前版本（加宽、窄桥、失败演出），当场修正手感问题。
2. 主线：坠落救援。
3. 穿插：中途存档点、失败原因高亮。
4. 之后再从方向一、方向二中选下一项。

## 坠落救援（已实现，待试玩）

2026-10-14 在 `feature/fall-rescue` 实现，规则如下；专项检查 `tests/fall_rescue.gd`。尚未经过真人试玩，频率与时限为初值。

参数均为试玩初值，可调整。

- **触发**：一人失去地面支撑（断崖缺口、窄桥、碎裂石板、走出路边），而另一人仍站在地面上且有支撑时，进入救援。两人同时失去支撑、队友正在腾空，或被危险撞击，仍按现有规则直接失败。
- **世界冻结**：救援期间自动推进、危险运动、机关和计时全部冻结（同暂停），只运行救援。保证公平，也便于联机帧同步。
- **按键**：救援者连按自己的跳跃键（01 空格、02 回车；触屏点右半屏）。只计按下边沿，按住不算。
- **进度**：进度条从 0 开始，每次按下增加一段，同时持续回落；限时 3 秒。进度满即救起，超时则落下并播放现有坠落演出、共同失败。
  - 所需频率按难度调整：简单约每秒 4 次，普通约每秒 5.5 次，困难约每秒 7 次。
- **救起后**：坠落者回到失足前最后一个有支撑的位置，获得 1 秒无敌；自动推进按现有恢复曲线逐渐恢复全速。
- **重复救援**：同一关内每多救一次，所需频率提高约 15%，避免无限救援把坠落惩罚变得无意义。
- **表现**：坠落者挂在崖边绳下，绳子绷紧发光；救援者后仰拉绳；屏幕显示进度条和"02 狂按回车！"之类提示；镜头复用失败演出的崖边机位。
- **验证影响**：生成路线控制器从不坠落，现有段落证书不受影响。需新增救援专项测试：频率足够救起、频率不足坠落、冻结期间危险不动、联机两端结果一致。

- **坠落者协助**（2026-10-14 用户确认）：坠落者也可连按自己的跳跃键往上爬，每次按下的效果为救援者的一半。
