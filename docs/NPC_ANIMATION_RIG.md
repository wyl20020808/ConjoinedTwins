# NPC 骨骼动作：自动绑定与程序化动作

日期：2026-10-20。分支：`feature/npc-animation`。

## 问题

六种怪物与四种村民都是 Tripo 生成的静态网格（单网格、约 4–5k 顶点、没有骨骼）。怪物原先靠整体摇摆和前倾假装走路，村民只有 DP 加的顶点摆动。另外狼与树精的模型原生朝 +Z，代码统一转了 -90°，所以它们一直侧身朝玩家移动。

## 做法：`build-tools/journey/rig_npcs.py`

在 Blender 5.2 后台运行，不依赖外部骨架和重定向，所有轴向由脚本自己定义：

1. **自动推关节**：
   - 双足：贴地顶点聚类出两只脚；按高度切片取躯干质心得到骨盆、胸、颈；胸部切片宽度以外的顶点归为手臂，离肩最远的一批点作为手（武器跟着手动）。
   - 四足：贴地顶点聚成四只爪，按前后分出肩、髋；最前端为鼻尖，最后端为尾尖。
2. **权重**：Tripo 网格是非流形碎片，Blender 自动权重整体失败，改为按"到骨段距离"的高斯衰减算权重，每个顶点最多 3 根骨。双足还加了区域限制：
   - 手臂骨只管躯干宽度以外、且不在身体后方的顶点，头发、斗篷、背包不会被手带走；
   - 腿骨只管骨盆以下的顶点。
3. **动作**：在模型空间的"前 / 左 / 上"轴上直接写关键帧。
   - 怪物：Idle、Walk、Run、Attack、Hit；
   - 村民：另有 Talk、Look。
   - 攻击分四种：单手挥击（劫掠者、冲锋者）、双手砸地（石卫）、拉弓（弓手）、扑咬（狼、树精）。
   - 步幅按体型缩放，例如石卫 0.5、树精 0.7。
4. `--preview` 时渲染各动作的侧面和 3/4 正面检查图。

另有 `npc_turnaround.py`，渲染带 0.1 网格的正视、侧视剪影，用于确认朝向与比例。

## 接入

- **怪物**（`journey_enemy_view.gd`）：
  - 模型换成 `assets/monsters/rigged/`；狼与树精不再转 -90°。
  - 播放位置完全由模拟量决定，动画自己不走时间，暂停时自然定格：
    - 走 / 跑：用模拟的 `stride` 相位，脚步与位移同步；
    - 预警期：播攻击的蓄力段（0–45%）；
    - 出手期：播挥击段；
    - 受击、倒地：播 Hit。
  - 原来的整体摇摆和前倾在有骨骼时清零。
- **村民**（`journey_landscape.gd`）：
  - `assets/landscape/rigged/` 存在时，不再走 MultiMesh，改为逐个实例化，每区块只有几个人；
  - 按位置散列在待机、说话、张望中挑一个循环动作，并错开起始帧；
  - 区块预取路径同步指向绑定版。缺文件时退回原 MultiMesh 加顶点摆动。

## 局限

- 程序化动作，不是动捕：步态偏机械，攻击是三段式。
- 自动权重会让个别部件跟错骨头。弓手拉弓时弓身略有拉伸；商人背包已排除，若还有拉伸需要手工修正。
- 骨盆以下的长袍、围裙随腿一起弯，裙摆会有轻微折痕。
- 想要更自然的动作，可以把 `rig_npcs.py` 生成的骨架导入 Mixamo 或 AccuRIG 换动捕动作，脚本的骨骼命名可以保留。
- 没有真人试玩；只在 M4 上测过。
