## 范围与实际入口

最新 `test` 的生产入口已经是主动前进的连续旅程，并非上轮方案调查时分支中的自动推进道路。连续旅程保留既有固定关卡、事件位置、单向主动移动、绳索、跳跃、存档、机关和结算。环境装饰仍按原有区块种子生成，没有引入新的玩法随机性。历史道路入口及其随机地图同样保留并优化。

默认启动先运行 `scenes/journey_boot.tscn`，再加载原来的 `scenes/journey.tscn`。直接实例化旅程场景仍支持同步初始化，供既有夹具及直接运行场景使用。生产启动脚本无需改变：双击 `试玩连续旅程.command`，或运行：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path /Users/apple/ConjoinedTwins
```

## 三批实施

### 第一批：减少重复计算

- 固定音效由显式工具 `build-tools/bake_sfx.gd` 预生成 WAV。随后将三种 7 秒环境音也纳入同一工具。保留原公式，WAV 关闭有损压缩；全部 PCM 字节与基线一致。
- 道路缺口尺寸和边壁仅在绑定矩形改变时更新；闪烁与位置仍按生产时间同步。
- 在已有道路支撑签名缓存之上增加跨版本的局部切口网格缓存，最多 128 份；布局、槽位、运行实例和原点变化会重新匹配。
- 缓存资源原始包围盒、地面材质及动画目标，避免反复遍历相同模型。旅程的地面仅在实际缺口、裂纹或主题变化时重建，不因无关版本更新整批重建。

### 第二批：加载流水线与统一预算

- 轻量启动页先获得绘制机会，然后异步读取生产场景、贴图和角色；资源加载完成后才调用 `load_threaded_get()`，运行帧不等待未完成的读取。
- 首屏资源保持强引用，后续切换地貌可直接复用。资源 IO 同时最多两项；道路无人机、矿车模型也在预热阶段提前读取。
- 旅程区块拆成独立的模型、地面、植被和标牌安装指令，按帧执行，不再一次同步创建整个区块。事件、村民和出口机关在进入显示范围前准备。
- 活动窗口为当前区块及前方三个、后方一个，另准备前方两个区块；已完成和未完成区块合计最多七个。未完成模型保持隐藏，准备完成后才呈现。
- 原道路的证明、模型预热与同一轮联机追帧共用绝对截止时间。加载期总软预算 6ms，运行期 2ms；旅程区块准备使用 2ms 软预算。
- 单个固定物理验证步、模型实例化及 GPU 提交不可在中途打断，因此预算不是严格帧时上限。未通过降低物理步频、减少碰撞子步或修改绳索精度来换取性能。
- 固定旅程重试复用环境，刷新机关、动画与地面阶段；开局或恢复未准备好时不消费模拟时间。资源读取和计算任务在退出时正确收尾。

### 第三批：本机多核预计算与确定性

- 地图验证通过 Godot `WorkerThreadPool` 分发，最多两个并行任务，可设为一个；资源 IO 队列独立限流。没有引入外部服务器或在线 API。
- 先按原抽签顺序生成请求，各验证任务持有独立数据和随机状态；完成顺序不决定地图安装顺序。
- 旅程区块规划是纯数据计算，各区块保留原种子 `number * 109 + chapter * 7919 + 42`，保留随机数调用顺序。后台生成规划，主线程分帧安装场景节点；工作线程不修改活动场景树。
- 原道路根据实际生成耗时扩大预读证明窗口，最低四段、最多八段；安装距离、候选顺序和生产随机序列保持原值。旅程提前两块，在最高合法速度下提供额外 20 秒准备时间。
- 重试、切关及释放时废弃旧任务，取消标记仍通过 Mutex 访问；运行轮询只取已完成结果。退出和取消收尾仍需等待活跃任务到达取消检查点，不声称任意任务可瞬间终止。
- 无线程路径保留可暂停验证器。没有把同步集中补算作为生产兜底，也没有修改旧夹具来掩盖失败。

## 性能实测

机器为 Apple M4、16 GiB 内存，Godot `4.7.1.stable.official.a13da4feb`。使用同机新进程，基线与优化版串行交错各运行三次；表中为每轮对应统计量的中位数。OS 文件缓存未清空，初次导入与进程启动不在计时内。基线脚本、场景和项目配置从原始提交提取，素材及导入缓存复用相同本地内容。

所有数据均为 **headless CPU 或准备墙钟时间**，不是渲染 FPS、GPU 帧时、磁盘冷启动或真人设备验收。

| 指标 | 原始 test | 优化后 | 耗时减少比例 |
| --- | ---: | ---: | ---: |
| 音效初始化 CPU 中位数 | 62.394 ms | 1.093 ms | +98.25% |
| 道路原生开局墙钟 | 2077.791 ms | 1170.040 ms | +43.69% |
| 道路原生准备主线程 CPU 总量 | 2046.376 ms | 12.090 ms | +99.41% |
| 道路无线程开局墙钟 | 2138.893 ms | 2197.906 ms | -2.76% |
| 道路无线程准备调用 P95 | 8.500 ms | 8.424 ms | +0.89% |
| 道路缺口视图 CPU P95 | 0.180 ms | 0.160 ms | +11.11% |
| 旅程直接场景就绪墙钟 | 659.601 ms | 443.731 ms | +32.73% |
| 旅程稳定视图 CPU P95 | 0.289 ms | 0.250 ms | +13.49% |

默认旅程启动流水线的准备就绪墙钟为 **343.211ms**；对照原始同步场景的 659.601ms，约减少 48.0%。轻量加载 UI 的构造耗时为 3.465ms；这仅证明 UI 提前建立，未声称已测得真实显示器上的首帧时间。

区域跳转夹具中，原始同步创建的每轮峰值中位数为 **471.130ms**；优化后已经准备完成的视图刷新峰值中位数为 **0.669ms**，分帧准备调用峰值中位数为 **2.339ms**。两者不是同等工作量的总耗时比较：资源读取和模型创建已移到提前的后台任务及多个准备帧，不能据此宣称总计算量减少数百倍。三轮最高合法前进速度的窗口推进测试，途中等待均为 **0**。

无线程开局墙钟增加 **2.76%**，没有宣称该路径获得提速。它保留确定性和分帧能力；预算合并不能消除同一条线程必须完成的全部验证计算。加载期准备调用仍可能超过 6ms 软预算。原生路径主要收益是将地图验证从主线程移至后台，并行缩短等待。

音效初始化统计包含同进程五次初始化，不把它称为独立游戏磁盘冷启动。稳定视图使用固定生产布局和相同调用次数；区域跳转为覆盖三关十八区域的人工进度夹具，正常路线通关由另一个测试验证。
