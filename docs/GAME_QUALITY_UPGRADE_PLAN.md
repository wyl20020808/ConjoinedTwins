# 游戏质感升级方案（待用户确认，未实现）

日期：2026-10-20。依据：`test@92f6661` 的源码、`docs/` 各轮报告（FX P1–P4、LOOKDEV 各刀、角色/NPC 动画、联机追帧、网页导出）和本轮存档点测试。没有真人试玩，也没有在本轮做可见 GUI 验收；画面判断来自代码与既有报告，需试玩复核。

## 一句话结论

画面（PBR 素材、AgX 色调、体积雾、SSAO、特效四刀）已经接近成品水准；最拉低质感的是**声音**（无音乐、合成"哔"声）、**失败—重试的等待与挫败**、**跳跃/受击这类瞬间反馈**，以及**强度恒定、缺少呼吸的关卡节奏**。建议先做 P0 四项，每项 1–6 天，互不依赖，可以并行。

## 需要你先拍板的三件事

这几项和既有规则或你之前的决定有关，方案里给了做法，但要你确认方向：

1. **镜头**：规则是“固定朝向、不旋转、不晃动”。B3 只做平移和 FOV 微调（前视偏移、大场面稍拉远），不旋转不晃动——是否允许？
2. **危险提示**：之前决定隐藏全部红黄警告、落点框和预警音效。B1 建议用“环境内”提示（阴影、前摇动作、声音）代替 UI 标记，并在难度里提供“辅助提示”开关——是否接受？
3. **受击画面冲击**：A3 用 1–2 帧色差/径向模糊代替镜头晃动——是否算违反“不晃动”？

## P0：投入小、收益最大

### A1 失败—重试循环

- **现状**：撞击失败演出 1.6 秒、坠落 2.6 秒，结束后弹失败面板，需按键或点按钮“从存档点继续”。本轮已加密存档点（平均回退距离下降约 62%，见 [存档点加密](CLOSER_CHECKPOINTS.md)）。保存存档时没有任何提示。
- **问题**：每次失败约 3–4 秒等待再加一次确认；玩家不知道下一次会从哪里开始。同类合作动作游戏重试一般在 1.5 秒内。
- **改法**：
  1. 演出 0.6 秒后允许任一玩家按跳跃跳过（联机按模拟帧号同步，两端同一帧生效）。
  2. 失败面板改为屏幕下方一行“按跳跃从存档继续 · Esc 菜单”，不再盖住画面。
  3. 恢复时 0.25 秒黑场淡入淡出，作为转场，不改变恢复位置和判定。
  4. 存档时 HUD 角落出现 0.8 秒小图标和一声轻音效，让玩家知道“这里存了”。
- **预期效果**：重试等待由约 4 秒降到约 1.5 秒；“死得不冤”。
- **工作量**：S，1–2 天。
- **风险**：联机跳过时机需要同步；`journey_failure_presentation` 测试要随之更新。

### A2 音乐与混音

- **现状**：没有背景音乐。16 个音效由 `scripts/sfx.gd` 程序合成（22 kHz 方波/锯齿/噪声，如跳跃是上扫方波），另有森林、河流、风声三段底噪和鸟鸣。全部走 Master 单总线，10 个不定位播放器轮换。画面已隐藏预警，预警音效也已去掉。
- **问题**：合成“哔哔”声和写实画面割裂，是当前最明显的“原型感”来源；没有音乐，节奏和情绪全靠画面；声音没有方位，听不出危险从哪边来。
- **改法**：
  1. 建 Music / SFX / Ambience / UI 四条总线，Master 加限幅；战斗时自动压低环境声（sidechain ducking）。
  2. 每章一首分层音乐：探索层常驻，战斗鼓点层按附近存活敌人数淡入，合作机关层在门前淡入；层间按小节对齐切换。
  3. 用 CC0 或已购素材替换合成音效：脚步按地面材质分（石板、泥路、木桥、矿道）；枪声带尾音和远近两层；怪物的预警、受击、倒下各一组；压机、摆锤、水车、滚球的机械声；绳子绷紧的吱嘎声。
  4. 机关和敌人改用 `AudioStreamPlayer3D`，有距离衰减和左右声像；每次播放随机音高 ±5%、音量 ±2 dB，避免机械重复。
  5. 机关蓄力和敌人前摇加可辨识的短声，补上“不画警告”之后缺失的提示。
- **预期效果**：质感提升最显著的一项；危险可以靠耳朵预判。
- **工作量**：M，4–6 天（含素材挑选与授权登记）。
- **风险**：素材授权须登记到 `ASSET_SOURCES.md`；网页包体积（音乐用 ogg 流式，音效短小）；浏览器需首次点击后才能出声（开始按钮可解锁）。

### A3 命中与受击手感（在固定镜头下）

- **现状**：已有枪口焰、曳光、弹壳、命中碎屑、击杀余烬、敌人预警红边光、受击暗角和低血量反馈（FX P3、LOOKDEV 第四刀）。按规则镜头不晃动。没有手柄震动和手机触觉。
- **问题**：缺少停顿帧，敌人受击几乎不位移，射击没有后坐表现，命中和击杀的“确认感”偏弱。
- **改法**：
  1. 视图层停顿帧：击杀或重击时角色、敌人动画和粒子暂停 40–60 ms；只停渲染层，不停固定步模拟，联机不受影响。
  2. 敌人受击小幅后仰与击退（模拟层，按命中帧固定位移，保持联机确定性）。
  3. 枪械后坐：上半身骨骼叠加小幅抬枪，连射逐渐累积，停火回位。
  4. 击杀确认：短促音效 + 锁定框收缩。
  5. 触觉：手柄 `Input.start_joy_vibration`，手机 `Input.vibrate_handheld`，用于受击、重落地、开门。
  6. 受击 1–2 帧色差或径向模糊代替镜头晃动，设置里可关（需你确认，见上文）。
- **预期效果**：射击和受伤更有分量，不碰固定镜头约束。
- **工作量**：M，3–4 天。
- **风险**：击退会改变模拟，需要更新确定性测试和联机指纹；停顿帧要避免影响 HUD 和输入。

### A4 跳跃与移动动画

- **现状**：主角动作已在 Blender 本地烘焙（27 个 clip，见 `CHARACTER_ANIMATION_FIX.md`）；其中 Jump 是 Idle 姿势加髋部起伏和屈膝合成的。横移只给根节点 ±0.42 弧度偏航。NPC 是自动绑定加程序化动作。
- **问题**：跳跃没有起跳预备、腾空、落地缓冲三段，像整体平移；台阶和坡道上脚不贴地；横移是“转身跑”而不是侧步；持枪时上下半身一起动。
- **改法**：
  1. 用现有烘焙流程（`build-tools/journey/bake_hero_animations.py`）加入 Jump_Start / Jump_Air / Jump_Land 三段，`AnimationTree` 状态机按竖直速度切换，落地按下落速度决定缓冲轻重。
  2. 播放速度按实际水平速度缩放，消除滑步。
  3. 双脚 IK 贴地，处理台阶、坡道、升降台。
  4. 横移和后退用 BlendSpace2D 侧步。
  5. 持枪动作放在上半身层，下半身独立跑动。
- **预期效果**：角色从“会动的模型”变成“有重量的人”，双人合作时的动作对视更清楚。
- **工作量**：M–L，5–8 天。
- **风险**：01 的 Tripo 骨架有历史问题，必须沿用烘焙流程；网页 CPU 预算；救援、死亡动作切换需回归。

## P1：明显提升，需要更多设计或验证

### B1 危险可读性：环境内预警

- **现状**：所有红黄警告、落点框、轨迹线和预警音效已隐藏，只保留道具本身；FX P1 为机关加了阶段切换特效和运动拖尾。
- **问题**：2.5D 纵深镜头下前后距离难判断，机关约每 12 米一拍，信息过载时玩家无法预判，失败容易显得“不公平”。
- **改法**：
  1. 所有飞行物和落石在地面投下随高度缩放的圆形接触阴影（远处实时阴影会糊）。
  2. 统一 0.3–0.6 秒前摇姿态：压机上抬抖动、地刺缝隙冒尘、塌陷路面裂纹加深并掉渣。
  3. 配合 A2 的声音提示。
  4. 难度设置里加“辅助提示”，可重新打开原来的地面预警。
- **预期效果**：玩家能说出自己为什么死，重试意愿更高。
- **工作量**：M，4–5 天。
- **风险**：与“隐藏警告”的既有决定相关，需你确认；不得改变判定时长。

### B2 关卡节奏曲线

- **现状**：每章 6 区；主机关约每 12 米一拍，同侧三拍成组，组间 20 米；敌群每 45 米一群，每群 3–5 只；随机配比有上下界。
- **问题**：强度几乎恒定，没有“紧张—释放”。本轮测试中，第三章 400–2500 单位之间连续是窄路、摆臂、敌群和滚球，没有一个可以安全站定的时刻。长时间高压让人疲劳，地标和奖励时刻也不突出。
- **改法**：
  1. 每个区域设强度曲线：入口 15–20 秒“呼吸段”（风景、补给、存档），中段逐步加密，末段一个招牌组合，合作门作为高潮后的休息。
  2. 随机生成器按曲线控制密度，而不是全区均匀抽取。
  3. 每章 1–2 个手工编排的场景时刻（例如倒塌的木桥、水车全景）。
- **预期效果**：节奏有起伏，挫败感下降，场景被记住。
- **工作量**：L，1–2 周（含生成器改动与可通行证明）。
- **风险**：牵动随机生成、密度测试和性能门槛；所有布局需要重新证明可通行。

### B3 镜头与构图（只平移、不旋转）

- **现状**：FOV 57，镜头按进度固定偏移跟随；失败和救援有特写机位。
- **问题**：完全刚性的跟随，速度感弱；合作门等大场面没有呈现；快速前进时前方视野偏少。
- **改法**（只改位置和 FOV，需你确认）：
  1. 前视偏移：按两人前进速度把焦点前移 1–2 米，临界阻尼平滑。
  2. 合作门和大型机关前镜头后移约 2 米（或 FOV 57→62），离开后回位。
  3. 章节开场 3 秒推镜加章节名卡片。
- **预期效果**：前方更好读，大场面更有气势。
- **工作量**：S–M，2–3 天。
- **风险**：与镜头规则的边界；FOV 变化会影响远景加载与机关距离判断。

### B4 HUD、菜单与设置

- **现状**：玻璃风格 HUD（双人血条、武器弹药），开始/暂停/失败面板统一样式。没有设置页、音量、画质选项、按键重映射或手柄支持；不显示章节进度。
- **问题**：现代游戏标配的设置与无障碍缺失；玩家不知道离出口还有多远、身处哪个区域。
- **改法**：
  1. 设置页：总/音乐/音效音量；画质预设（阴影、体积雾、SSAO、渲染缩放）；帧率上限；伤害数字开关。用 `ConfigFile` 保存，网页存到浏览器本地。
  2. 手柄支持：InputMap 增加手柄事件，按钮图标随输入设备切换。
  3. 顶部细条显示章节进度、区域名和存档位置。
  4. 进入区域时区域名淡入（六个区域名已存在）。
  5. 无障碍：色弱模式（01/02 配色可换）、关键音效的文字提示。
- **预期效果**：完成度和可用性追上同类作品。
- **工作量**：M，4–5 天。
- **风险**：联机时暂停与设置的语义；本地双人共享键盘时的按键冲突。

### B5 联机与网页体验

- **现状**：60 Hz 帧同步中继；刚修了积压追帧（稳态缓冲 2 帧）；网页 brotli 预压缩；网页用 Compatibility 渲染，3D 缩放到约 960×540，限 60 fps。
- **问题**：看不到延迟和连接状态；断线后不能重连；只能输入地址，没有房间码；首次加载等待长；网页画质与桌面差距大。
- **改法**：
  1. HUD 显示往返延迟和连接状态，延迟高时提示。
  2. 断线重连：服务器保留最近快照和输入日志，重连客户端追帧。
  3. 四位房间码和邀请链接。
  4. 网页分包：先下载核心场景，章节资源按需下载；加载页显示真实进度和操作提示。
  5. 网页画质分档：桌面浏览器提高渲染缩放并启用简化雾效。
  6. 按延迟自适应 2–4 帧输入缓冲。
- **预期效果**：远程合作从“能玩”到“愿意约朋友玩”。
- **工作量**：L（可拆分，重连最重）。
- **风险**：确定性回归；中继服务器改动和部署需要授权；与刚完成的追帧修复互相影响。

## 建议顺序

1. **第一批（约 1 周，可并行）**：A1 重试循环、A2 音乐与混音、A3 命中手感。三者文件基本不重叠（失败流程/音频/战斗视图）。
2. **第二批**：A4 动画，B4 设置（A2 的音量需要它），以及你确认后的 B1、B3。
3. **第三批**：B2 节奏曲线、B5 联机网页体验，各自单独排期并补验证。
4. P2 视试玩反馈再定。

每项完成后都需要真人试玩确认；涉及旅程密度、碰撞、资源加载的项目照常串行运行 `build-tools/check_journey_performance.py`。
